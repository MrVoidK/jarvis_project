**Durum:** onaylandı, uygulanmayı bekliyor

## 1. Amaç ve kapsam

Jarvis'e mikrofon/terminal dışında iki yeni girdi kaynağı eklenir:

- **Scheduled** — cron ifadesiyle zamanlanmış, önceden tanımlı komut metinleri
  (`config/scheduled_tasks.yaml`).
- **Continuous** — bir koşulu (bu fazda: bir dosyanın mtime'ı) izleyen daemon
  thread; koşul tetiklenince önceden tanımlı bir komut metni üretir.

**Kritik ilke (v2 §5, değişmez):** Yeni kaynaklar HİÇBİR yeni güvenlik yolu
açmaz. Üretilen her olay, mevcut `_handle_turn()` → guardrail → dispatcher →
`_run_tool_pipeline()` zincirinden aynen geçer. Tek fark: `InputEvent.source`
alanı ve aşağıdaki (§5) runtime risk kapısı.

### Zaten yapılmış olan (Faz 6.4)

`core/registry_loader.py:191-205` şunu **zaten** uyguluyor:
`execution_mode ∈ {on_demand, scheduled, continuous}` doğrulaması + bir manifest
`execution_mode: scheduled|continuous` işaretliyse ve `risk_level` MEDIUM+ ise
**boot'ta reddedilir** (`_skip` + `print_system`). Bu faz onu tekrarlamaz;
üstüne **runtime** tarafını (§5) ekler.

### Kapsam dışı (YAGNI / sonraki fazlar)

- Zamanlama durumunun restart'lar arası kalıcılığı — kapalıyken kaçan cron
  kaçmıştır (kabul edilen sınır).
- `/approve <id>` / `/deny <id>` ile bekleyen onayın tüketilmesi (deferred aracı
  sonradan çalıştırma) — ayrı bir takip işi. Bu faz yalnızca **kaydeder ve
  gösterir**.
- Timezone yapılandırması — cron yerel saatte yorumlanır (`croniter` varsayılanı).
- `file_mtime` dışında watcher tipi.
- Config hot-reload — yeni görev/watcher için Jarvis restart edilir.

## 2. Bileşenler

### 2.1 `core/input_hub.py` — küçük genişleme

```python
InputSource = Literal["voice", "text", "scheduled", "continuous"]
```

- Yeni public metot `InputHub.submit_event(event: InputEvent) -> None` —
  `self._queue.put(event)` (stdlib kilidiyle korunuyor, herhangi bir thread'den
  güvenli, bkz. mevcut `submit_external_text` docstring'i).
- `submit_external_text(text)` → `self.submit_event(InputEvent("text", text))`
  ince sarmalayıcısına indirgenir (davranış aynı).
- **Değişmez:** `wait_for_text_answer()` yalnızca `event.source == "text"` olanı
  onay cevabı sayar; `scheduled`/`continuous` olaylar zaten `pending`'e eklenir
  ve onay sonrası normal tur olarak işlenir. Ek kod gerekmez — sadece test.
- `InputHub.__init__` yapısal olarak **değişmez** (mic + text thread'leri sabit).
  Scheduler ve ContinuousRunner ayrı nesneler; `run_jarvis()` onları kurar,
  başlatır ve `stop_event` ile kapatır.

### 2.2 `core/scheduler.py` (YENİ)

```python
@dataclass(frozen=True)
class ScheduledTask:
    name: str
    cron: str
    text: str

@dataclass(frozen=True)
class WatcherSpec:
    name: str
    type: str          # bu fazda yalnızca "file_mtime"
    params: dict        # {"path": ..., "text": ...}

def load_scheduled_config(
    path: str = CONFIG_PATH,
) -> tuple[list[ScheduledTask], list[WatcherSpec]]:
    ...
```

**Yükleme sözleşmesi:**

| Durum | Davranış |
|---|---|
| Dosya yok | `([], [])` döner — özellik sessizce kapalı (opt-in) |
| Dosya var, YAML bozuk | `raise` (`security_config.load_security_config` deseni) |
| Dosya var, `scheduled`/`watchers` anahtarı yok | o liste `[]` |
| Bir görevde `name`/`cron`/`text` eksik | `raise ValueError(f"scheduled task {i}: eksik alan ...")` |
| Bir görevde geçersiz cron | `croniter` hatası yakalanıp `raise ValueError(f"scheduled task {name}: geçersiz cron {cron!r}")` |
| Bir watcher'da bilinmeyen `type` | `raise ValueError(f"watcher {name}: bilinmeyen type {type!r}")` |

`CONFIG_PATH = PROJECT_ROOT/config/scheduled_tasks.yaml`,
`EXAMPLE_PATH = .../scheduled_tasks.example.yaml` (repoya commit'lenir,
`security.example.yaml` gibi). Gerçek dosya `.gitignore`'a eklenir.

**`Scheduler` sınıfı:**

```python
class Scheduler:
    def __init__(self, hub, stop_event, tasks: list[ScheduledTask],
                 poll_interval: float = 30.0,
                 now_fn: Callable[[], datetime] = _utc_now): ...
    def start(self) -> None:   # daemon thread "jarvis-scheduler"
```

Döngü:

```
last_check = now_fn()
while not stop_event.wait(poll_interval):   # kesintiye uğrar (graceful shutdown)
    now = now_fn()
    for task in tasks:
        nxt = croniter(task.cron, last_check).get_next(datetime)
        if last_check < nxt <= now:
            hub.submit_event(InputEvent("scheduled", task.text))
    last_check = now
```

Due-window başına bir kez tetikler (birden fazla cron hit birikirse yine tek
olay). `now_fn` enjekte edilebilir → testte sahte saat.

### 2.3 `core/continuous_runner.py` (YENİ)

```python
class ContinuousWatcher(ABC):
    name: str
    @abstractmethod
    def check(self) -> Optional[str]: ...   # tetiklendiyse olay metni, yoksa None

class FileMtimeWatcher(ContinuousWatcher):
    def __init__(self, name: str, path: Path, text: str):
        self._last_mtime = self._current_mtime()   # ilk check'te tetiklenmesin
    def check(self) -> Optional[str]:
        m = self._current_mtime()          # dosya yoksa None
        if m is not None and m != self._last_mtime:
            self._last_mtime = m
            return self._text
        return None

def build_watchers(specs: list[WatcherSpec]) -> list[ContinuousWatcher]:
    # type == "file_mtime" -> FileMtimeWatcher; başka tip zaten load'da elenmiş

class ContinuousRunner:
    def __init__(self, hub, stop_event, watchers: list[ContinuousWatcher],
                 poll_interval: float = 5.0): ...
    def start(self) -> None:   # daemon thread "jarvis-continuous"
```

Döngü: `while not stop_event.wait(poll_interval):` → her watcher için
`try: result = w.check()` / `except Exception: logger.warning(...)` (bir bozuk
watcher thread'i öldürmez); `result` doluysa
`hub.submit_event(InputEvent("continuous", result))`.

### 2.5 `core/app.py` — runtime risk kapısı

**Gerçek çağrı zinciri** (kod okundu):
`_handle_turn(user_text, ...)` → `_execute_tool(tool, intent, ...)` →
`_run_tool_pipeline(tool, intent, ...) -> str`. `_run_tool_pipeline` tek bir
`str` döndürür (araç sonucu / yerelleştirilmiş mesaj); `_handle_turn` bunu
`yield result, lang` ile bir cümle olarak akıtır.

İki yeni parametre üç fonksiyona da eklenir, hepsinde geriye dönük uyumlu
varsayılan (`source="voice"`, `event_text=""`):

```
_handle_turn(user_text, history, *, source="voice", ...)     # event.source, event.text
  -> _execute_tool(tool, intent, ..., source=source, event_text=user_text)
     -> _run_tool_pipeline(tool, intent, ..., source=source, event_text=event_text)
```

`_run_tool_pipeline` içinde: **(1) parametre guardrail'i AYNEN çalışır** (bir
scheduled görevin parametresi `rm -rf` içeriyorsa yine reddedilir/loglanır —
pending kaydına dönüşmez). Sonra onay noktasında (mevcut satır ~272
`if requires_approval(tool.risk_level):` bloğunun EN BAŞINDA):

```python
if requires_approval(tool.risk_level):
    if source in ("scheduled", "continuous"):
        task_id = record_pending(
            source, event_text,
            {"tool": tool.name, "risk": tool.risk_level.value, "params": risky_values},
        )
        logger.info("[%s] MEDIUM+ eylem onaya alındı (#%s): %s", source, task_id, tool.name)
        print_system(
            f"[{source}] istek '{tool.name}' ({tool.risk_level.value}) gerektiriyor — "
            f"otomatik çalıştırılmadı, onay bekliyor (#{task_id}).",
            level="warning",
        )
        return _localized(_PENDING_RECORDED_MESSAGES, lang)   # kısa bildirim; loglanır + (dinleyen varsa) seslendirilir
    # ... mevcut _prompt_for_approval yolu (voice/text) aynen ...
```

- Dönen kısa bildirim string'i her araç sonucu gibi `_handle_turn` tarafından
  `yield` edilir — ayrı bir "sessiz dönüş" yolu **eklenmez** (dinleyici yok,
  tutarlılık > mikro-optimizasyon). `_PENDING_RECORDED_MESSAGES` yeni bir
  TR/EN mesaj sözlüğü (`_APPROVAL_DENIED_MESSAGES` deseninde).
- LOW araç + scheduled/continuous → bugünkü gibi otomatik çalışır (zaten onay
  gerekmiyor, `requires_approval` False).
- `voice` / `text` kaynak → **tamamen değişmez**; mevcut `request_approval` /
  `wait_for_text_answer` yolu aynen.
- `record_pending` fail-soft `None` dönerse: `#None` yerine bildirimde "kayıt
  edilemedi (bkz. log)" varyantı; eylem yine çalışmaz.

### 2.7 `run_jarvis()` wiring

`hub.start()` ve `api.register_input_hub(hub)` sonrası:

```python
sched_tasks, watcher_specs = load_scheduled_config()   # dosya yoksa ([], [])
if sched_tasks:
    Scheduler(hub, stop_event, sched_tasks).start()
    print_system(f"{len(sched_tasks)} zamanlanmış görev yüklendi.", level="info")
if watcher_specs:
    ContinuousRunner(hub, stop_event, build_watchers(watcher_specs)).start()
    print_system(f"{len(watcher_specs)} sürekli izleyici yüklendi.", level="info")
```

`load_scheduled_config()` bir `raise` ederse `run_jarvis()` başlamaz (fail-loud,
opt-in dosya bozuksa) — kabul edilen davranış.

Döngüde (`while not stop_event.is_set()`): `event.source == "text"` CLI kontrolü
zaten var; `scheduled`/`continuous` olaylar `print_agent("User", event.text)` ile
loglanır ve `_handle_turn(event.text, ..., source=event.source)` çağrılır.

```

                          │
FileMtimeWatcher.check() ─┤ (mtime değişti)
  ──► hub.submit_event(InputEvent("continuous", text))
                          │
                          ▼
        run_jarvis: event = hub.next_event()
          source != "text"  ──►  (CLI kontrolü atlanır)
          print_agent("User", text)
          _handle_turn(text, ..., source=<source>)
            guardrail (değişmez)
            dispatcher → tool seçer
            _run_tool_pipeline(source=<source>):
              ┌─ source ∈ {scheduled,continuous} ve risk ≥ MEDIUM
              │     └─► record_pending(...) + print_system + return  (çalışmaz)
              └─ değilse
                    └─► mevcut yol: LOW auto / voice|text onay akışı
```

## 4. Hata yönetimi

| Yer | Strateji |
|---|---|
| `config/scheduled_tasks.yaml` yok | Özellik kapalı (`([], [])`) |
| Opt-in config bozuk / geçersiz cron / bilinmeyen watcher type | `load_scheduled_config` **raise** → `run_jarvis` başlamaz (fail-loud) |
| `FileMtimeWatcher.check()` istisnası | `logger.warning` + döngü sürer (thread ölmez) |
| `record_pending` DB hatası | **fail-soft** (`logger.warning` + `None`); scheduled tur sessizce düşer, Jarvis çökmez |
| Scheduler/Runner uyku | `stop_event.wait(poll)` — Ctrl+C / `/exit` ile anında kesilir (daemon thread) |
| croniter kurulu değil | `core/scheduler.py` import'u `run_jarvis` içinde gecikmeli; net `ImportError` mesajı ("`pip install croniter`") |

## 5. Test planı

Tümü hermetik (gerçek mikrofon/model/ağ yok), `python -m pytest tests/ -v`.

### `tests/test_scheduler.py`
- `load_scheduled_config`: dosya yok → `([], [])`; geçerli dosya → doğru parse;
  eksik alan → `ValueError`; geçersiz cron → `ValueError`; bilinmeyen watcher
  `type` → `ValueError`; sadece `scheduled` / sadece `watchers` olan dosyalar.
- `Scheduler` fire mantığı: enjekte `now_fn` + sahte `hub` (`submit_event`
  kaydeden). `cron="*/5 * * * *"`, saati 5 dk ilerlet → tam 1 olay; ilerletme
  yoksa 0 olay; iki periyot atla → yine 1 olay (birikmez).

### `tests/test_continuous_runner.py`
- `FileMtimeWatcher.check()`: değişiklik yok → `None`; `tmp_path` dosyasına
  dokun → 1 kez `text`, sonra `None`; dosya yok → `None`.
- `ContinuousRunner`: tek iterasyonluk sahte döngü (veya `stop_event` hemen set)
  + sahte watcher → `hub.submit_event` çağrıldı; `check()` raise eden watcher →
  runner hayatta, diğer watcher yine işleniyor.

### `tests/test_pending_tasks.py`
- `record_pending` → `tasks` tablosunda 1 satır (`db_path=tmp_path/...`),
  `status='pending'`, `detail_json` round-trip.
- `list_pending`: en yeni önce, `limit` uygulanıyor, boş DB → `[]`.
- Bozuk `db_path` → `record_pending` `None`, `list_pending` `[]` (raise yok).

### `tests/test_app_risk_gate.py` (veya mevcut app testine ek)
- Sahte dispatcher MEDIUM bir araç seçecek şekilde; `_handle_turn(text,
  source="scheduled")` → araç `execute` **çağrılmadı**, `tasks`'ta 1 `pending`
  satır.
- Aynı kurulum `source="scheduled"` + LOW araç → `execute` çağrıldı.
- `source="voice"` + MEDIUM araç → mevcut onay yolu (regression; mevcut testler
  kapsıyorsa yeni test yok).

### Enjeksiyon dikişleri
`Scheduler(now_fn=...)`, `ContinuousRunner(watchers=[...])`,
`record_pending(db_path=...)` / `list_pending(db_path=...)`,
`load_scheduled_config(path=...)`.

## 7. Değişmezler

1. Yeni girdi kaynakları yeni güvenlik yolu açmaz — aynı guardrail/dispatcher/
   risk zinciri.
2. `voice` / `text` davranışı bit-bit değişmez (`source` varsayılanı `"voice"`).
3. Scheduled/continuous'tan MEDIUM+ eylem **asla otomatik çalışmaz** — kayıt +
   kullanıcı dönünce karar (Zero-Trust "varsayılan RED"in uzantısı).
4. `pending_tasks` fail-soft — DB sorunu Jarvis'i çökertmez/bloklamaz.
5. Scheduler/Runner daemon + `stop_event` — graceful shutdown korunur.
6. Opt-in: `scheduled_tasks.yaml` yoksa hiçbir yeni thread başlamaz.
